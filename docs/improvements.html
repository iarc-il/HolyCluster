1 · Fix the broken data-retention & issues-table pipeline

CriticalData integrityEffort: S

The only known actively broken production defect. Two related failures:

  • The retention job crashes on the main table. backend/collectors/src/collectors/db/cleanup_postgres_tables.py:40 deletes rows where(model.date_time < cutoff) for both models, but HolySpot has no date_time column (only time and timestamp). Cleanup of holy_spots2 raises AttributeError, so the intended 14-day retention never happens and the table grows without bound. The job isn't in docker-compose either — confirm the external cron actually exists on both servers.
  • The issues table is write-dead. The fix_missing_spot.md runbook and the /spots_with_issues endpoint assume spots_with_issues2 is populated, but no code inserts into it — the collector silently drops problematic spots. The team's own debugging procedure no longer works.

(a) filter on HolySpot.timestamp (epoch int) instead of date_time; (b) re-add the insert into SpotsWithIssues where enrichment fails, with the failure reason; (c) schedule cleanup_postgres explicitly and add a test for it; (d) update fix_missing_spot.md to match reality.

2 · Run the existing test suites in CI

CriticalQuality gateEffort: S

Both test suites already exist — CI just never runs them. A push to dev deploys to the dev server having only passed linters; a tag deploys to prod the same way.

  • backend.yml runs only ruff check + ruff format --check; the pytest suites in backend/api/tests/ (WebSocket protocol, VOACAP, propagation) and backend/collectors/tests/ (parsers, enrichers, geo) are skipped. pytest isn't even a declared dev dependency.
  • ui.yml runs biome check + vite build, but not vitest — despite 23 test files and an existing npm run check script that does exactly lint+test.

3 · Security hardening — catserver bind address & QRZ credentials

HighSecurityEffort: S–M
  1. catserver listens on 0.0.0.0:3000 (catserver/src/server.rs:119), not 127.0.0.1. Anyone on the operator's LAN (or hostile Wi-Fi) can open the proxied UI, drive the WebSocket, and transmit-tune the user's radio — and hit /exit to kill the app. The design only ever needs localhost.
  2. The QRZ password travels in a URL query string (backend/shared/src/shared/qrz.py:93). Query strings end up in client logs, proxies, and exception traces. QRZ accepts POST form data; at minimum guarantee the URL never reaches a logger.
  3. Docker socket mounts (monitor, nginx_ui) are root-on-host equivalents. nginx_ui is dev-profile-only — good — but monitor runs in prod; consider a read-only socket proxy or document the tradeoff.

        CS -->|"SetModeAndFreq"| RADIO["radio transmitter"]
        CS -->|"POST /exit"| KILL["app killed"]
    end
    subgraph FIXEDNET["Fixed"]
        B2["local browser only"] -->|"127.0.0.1:3000"| CS2["catserver bound to loopback"]

bind 127.0.0.1 (keep an opt-in --bind flag for remote-desktop setups); move QRZ auth out of the query string; review docker-socket exposure. Also note nginx-ui/app.ini holds plaintext secrets in the working tree (gitignored, but visible to anyone with tree access).

4 · Enable Valkey persistence & graceful degradation

HighResilienceEffort: S

The Valkey service has its persistence volume commented out (backend/docker-compose.yml:32-34). Every restart — deploy, crash, host reboot — loses:

5 · Automated PostgreSQL backups — and move PGDATA out of the repo tree

HighDisaster recoveryEffort: M

There is no backup mechanism anywhere in the repo, and the live database files sit inside the git working tree as a bind mount (backend/infra/postgres/data/). The deploy script runs git reset --hard in that same tree on every deploy; gitignore is the only thing separating a routine deploy from data loss. The runbook even documents TRUNCATE TABLE geo_cache; as a casual step — with no restore path if the wrong table is truncated.

add a nightly pg_dump sidecar (or host cron) with rotation and an off-site copy; move PGDATA to a named volume or a path outside the repo; write a short docs/restore.md and rehearse it once. Postgres is the only stateful store that can't be regenerated.

6 · Retire the legacy WebSocket protocols

MediumSimplificationEffort: M

The versioned /ws protocol (v1) replaced older endpoints, but the old ones were never removed. Four parallel paths exist across three codebases:

Every spots broadcast is duplicated to two connection sets; catserver maintains two near-identical command enums; the UI ships dead socket code.

Old catserver installations are the main reason the legacy endpoints survive — which is exactly why the catserver auto-update nudge matters.

log per-endpoint connection counts for a few weeks; then delete the UI dead path (free), remove catserver's /radio handler and duplicate enum, and finally remove the backend legacy endpoints (or return a "please update" close code). End state: one protocol, one broadcast set, one enum.

7 · Repository & documentation hygiene

MediumOnboardingEffort: S

Individually small, collectively the first impression every new engineer gets:

  • README is wrong. It instructs pip install -e '.[omnirig]' and python src/ClientSideServer.py (README.md:53,58) — neither exists; the Rust catserver replaced them, and the backend moved to uv + docker compose long ago.
  • ~120 MB of log files at repo root (compose_logs_int_3.txt 41 MB, compose_logs_int_4.txt 79 MB) — untracked but not gitignored, polluting git status.
  • Shadow infra trees at the root (nginx/, certbot/, postgres/, nginx-ui/) shadow the authoritative backend/infra/ — an edit-the-wrong-file trap.
  • nginx.conf vs template drift: only the template is rendered at runtime; the committed rendered copy differs and misleads.
  • Minor: leftover debug log lines (see #8), the WiX installer's registry keypath under boilerplate Software\MyCompany\MyApp (catserver/wix/main.wxs:122-124), publish.sh:22 exit1 typo.
rewrite the README around the three real components (condensed from the architecture guide); delete the logs and gitignore compose_logs*; add pointers from the shadow trees to backend/infra/; delete or CI-regenerate the stale rendered nginx.conf; fix the WiX keypath.

8 · Bound the unbounded API endpoints & remove debug leftovers

MediumRobustnessEffort: S
  • GET /geocache/all (api/main.py:594) serializes the entire geo_cache table — no limit, no pagination — into memory per request. A refresh loop or crawler can spike API memory/CPU.
  • GET /spots_with_issues (api/main.py:612) is the same pattern (currently returns [] only because of defect #1 — fixing #1 makes this unbounded too).
  • /history contains leftover debug logging: logger.info("test 1s"), logger.info("test") (api/main.py:1068,1071).
  • No rate limiting anywhere; nginx is the natural place for a basic limit_req on /voacap and /history.
add limit/offset (sane default and max) to both dump endpoints — or restrict them to internal use; delete the debug lines; add a modest nginx limit_req zone for the expensive endpoints.

10 · Unify timestamps on UTC

LowerCorrectnessEffort: M

Spot timestamps mix timezone bases: add_spot_to_postgres builds HolySpot.time with local-time datetime.fromtimestamp(...) while timestamp is a UTC epoch (collectors/main.py:118), and the containers pin TZ=Asia/Jerusalem. The API's time-window queries and the UI's 1-hour trim all reason in epoch/UTC.

Consequences: the string time column disagrees with timestamp by the server's UTC offset; DST shifts it twice a year; anyone comparing time against a UTC source (or running with a different host TZ) gets subtly wrong windows — and the dedup key includes time.

write UTC everywhere (datetime.fromtimestamp(ts, tz=timezone.utc)); treat epoch timestamp as the single source of truth and derive display strings client-side; keep TZ pinning only for log readability; document the cutover date (backfill optional).
